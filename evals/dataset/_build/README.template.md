# Phase 1 eval dataset

{{CASE_COUNT}} synthetic healthcare documents with gold extractions for the three required IPS
sections (allergies, medications, problems) and the patient. Used by `evals/run_evals.py`
(PLAN.md Phase 1) and checked by `backend/tests/unit/test_eval_dataset.py`.

**All data is synthetic.** Names, clinics, people and identifiers are invented.
Finnish personal identity codes (HETU) use only individual numbers 900–999, the range never
issued to real people (they have valid check characters). Other identifiers use obvious test
prefixes (`SYN-`, `TST-`, `TW-`). Do not add real patient data.

> This file is generated by `_build/build.py` from `_build/README.template.md`. Edit the
> template, then rebuild.

## Layout

```text
evals/dataset/
  <case_id>/
    document.<txt|json|csv|pdf>   the input document
    gold.json                     expected IpsExtraction (schema 1.1.1, LLM JSON shape)
    meta.json                     case metadata (below)
  _build/                         deterministic generator (case definitions + builder)
  README.md                       this file
```

`meta.json`:

| field | values |
| --- | --- |
| `case_id` | directory name; `<lang><nn>_<doc>_<format>` |
| `language` | main language (= gold `document_language`): `fi`, `sv`, `en`; mixed documents are `fi+sv` / `fi+en` |
| `format` | `txt`, `json`, `csv`, `pdf` (the document's extension) |
| `media_type` | `text/plain`, `application/json`, `text/csv`, `application/pdf` (pass to `ingest`) |
| `doc_type` | `discharge_summary`, `referral_letter`, `prescription`, `medication_list`, `lab_report`, `outpatient_note` |
| `features` | feature tags, see the matrix below |
| `notes` | what the case tests and any judgement calls in its gold |

## Rebuilding

The dataset is generated gold-first: each case in `_build/cases_*.py` defines the synthetic
facts (as gold items with their verbatim quotes, built with the helpers in `_build/gold.py`) and
the document written from them. Run from `backend/`:

```sh
uv run python ../evals/dataset/_build/build.py
```

The builder renders the documents (PDFs with reportlab, `invariant=1`, so rebuilding gives
byte-identical files), ingests them with `app.pipeline.ingest`, fills each fact's `page` and
`locator` by locating its quote (ambiguous quotes must name the occurrence), validates the gold
with `IpsExtraction`, requires every quote to ground `exact` with no grounding flags, checks
that items are in document order, and rewrites this README. Generated files are checked in.
Synthea was not used: hand-written records give tighter control over the edge cases below.

## Gold-authoring rules

Gold follows the extraction prompt (`backend/app/llm/prompts/extract_v5.md`) and the schema
field descriptions. Where those leave room, these rules decide.

### Quotes and locations

- `source_quote` is the shortest contiguous span of the ingested text that supports every value
  set on the fact, copied verbatim (typos, abbreviations, case, inner spacing of fixed-width
  tables). Labels are included for labelled patient fields (`Henkilötunnus: …`, `Sex: F`,
  `DOB: …`); names are quoted without their label.
- CSV: one record is one segment (`header: value | …`); an item's quote is the row text from
  its first to its last supporting cell (in practice the whole row).
- JSON: when an item spans several leaves, the quote starts at the first supporting value and
  continues over the following segments exactly as `page_text()` joins them
  (`value\npath.key: value\n…`). Multi-line quotes in plaintext/PDF are joined with `\n`.
- `page` / `locator` are those of the segment where the quote starts (`""` for PDF pages).
- Items are listed in the document order of their quotes; allergy `none_known_statements` too.

### What counts as one item

- One substance / product / condition per item. A repeated entry (narrative + list, summary +
  diagnosis list, two languages) is reported once, quoting the most informative occurrence
  (usually the list line with dose or code).
- Problems: diagnoses and problems of the patient, current or past. Not: family history, other
  people's conditions, procedures/operations (appendectomy, prosthesis, cholecystectomy), lab
  findings without a written diagnosis, medication indications (these go to `reason_text`),
  and symptoms already explained by a stated (or suspected) diagnosis in the same passage.
  Presenting symptoms with no diagnosis (mx02) are problems.
- A current pregnancy written as a diagnosis line (Z32.1 "Raskaus todettu") is a problem; pregnancy
  history, last menstrual period, due date, height, weight, smoking, vaccinations and the contact
  person in the narrative are not, nor are results, vital signs, devices, alerts, advance
  directives, functional status, plans of care or the patient's own words (the schema has no place for
  them; fi13-fi18, sv07-sv08, en07-en08).
- Medications: every product the patient takes, took recently, or is prescribed now, including
  stopped and paused ones. Not: drugs only described generically ("IV antibiotics"), other
  people's medicines.
- Allergies: one item per substance; scoped "no known …" statements go into
  `none_known_statements` (D-7). "No other known allergies" / "Ei muita tiedossa olevia
  allergioita" only confirm the list and are not recorded.

### Section kinds

- `none_known` only for an explicit statement ("Ei tiedossa olevia allergioita", "Inga
  regelbundna läkemedel", "No known allergies", "Ei tiedossa." under an allergy heading).
- An empty JSON structure (`"allergies": []`) is not a statement: `no_information`.
- "No regular medication" followed by a newly prescribed drug is `items_found` (the schema has
  no scoped statements for medications; see en05).
- Scope of allergy statements: drug-specific wording (NKDA, lääkeaine-, läkemedels-) =
  `medication`; unspecified = `all`.

### Values

- Text fields copy the document's wording (no translation, no lemmatisation, typos kept).
  `condition_text` / `substance_text` / `medication_text` are the term only; laterality or a
  separate site phrase goes to `body_site_text` when it is written as a modifier
  ("oikean polven", "Polvien", "right lower lobe", "vasen korva"); `substance_text` drops an
  "allergy/-allergia/-allergi/-intoleranssi" ending ("Kala-allergia" → "Kala", "Latex
  allergy" → "Latex").
- Sites that belong to the diagnosis name: a site the name needs (a fracture, tear or failure
  *of* that structure) stays in `condition_text` and only its laterality goes to
  `body_site_text`: "Vasemman reisiluun kaulan murtuma" → "reisiluun kaulan murtuma" +
  "Vasemman" (fi06), "Fracture of lateral malleolus, left" → "Fracture of lateral malleolus" +
  "left" (en03), "nivelkierukan repeämä" + "oikean polven" (fi02), "Sydämen vajaatoiminta"
  (fi01). A site that only locates a disorder named on its own moves: "Polvien nivelrikko" →
  "nivelrikko" + "Polvien" (fi02), "Paksusuolen divertikuloosi" → "divertikuloosi" +
  "Paksusuolen" (mx01). Sites inside a compound word stay ("Keuhkokuume", "Ylävatsakivut").
- Printed codes (D-9) are copied when printed next to the entry and inside the quote;
  `printed_code_system_text` only when the quote itself names the system ("ATC", "ICD-10",
  or a JSON key such as `atc`). A system named only in a table header outside the quote is
  left empty.
- Enumerated qualifiers (allergy `type`, `criticality`, `severity`, `verification_status`) are
  set only when worded for that entry: "allergia/allergi/allergy" → allergy;
  "intoleranssi" → intolerance; "todettu/dx/diagnosed/varmistettu" → confirmed;
  "epäily/misstänkt/suspected" → `provisional` for a condition, `unconfirmed` for an allergy
  (allergies have no `provisional`); "keskivaikea/moderate" → moderate;
  "vaikea/severe" → severe. Allergy `category` may be inferred from the substance.
- `clinical_status` of conditions only from explicit wording ("parantunut", "utläkt",
  "resolved", "aktiivinen"/`status: active`); a heading such as "Aiemmat sairaudet" alone does
  not decide it (those lists mix ongoing and past illnesses).
- Medication `status` (the one qualifier that may come from the list the entry is in):
  `active` for current lists, discharge lists and new prescriptions; `stopped` for
  lopetettu/utsatt/stopped; `on_hold` for tauolla/tauotettu/uppehåll/on-hold. Wording in the
  entry's own line wins over the list heading.
- Dates only as precise as written (`03/2024` → `2024-03`, `Aug 2025` → `2025-08`). Birth date
  and gender only when stated; never derived from a HETU, so gold keeps `birth_date: null`
  when only a HETU is present. D-10 derivation is a deterministic pipeline step after
  grounding (`backend/app/pipeline/derive.py`), scored against `meta.json`
  `expected_patient` (the true birth date/gender; for HETU-only cases the date the synthetic
  HETU was generated from; never a gender, since 900-999 codes carry none). Titles ("Mr", "rouva") and pronouns are not a
  stated gender; "8-vuotias tyttö", "74-årig kvinna", "69-vuotias mies" are.
- Dosage: `text` is the instruction as written, including an indication written in it
  ("1x3 tarvittessa kipuun", "2 puffs PRN for wheeze"); an indication in a separate field or
  line (CSV column, JSON key, "Ändamål:" line) is not part of it. Structured parts only when
  they read off directly: `1 x 2`/`1x2`/`BD`/`BID` → 2 per 1 d, `OD`/`ON` → 1 per 1 d,
  `TDS` → 3, `QDS` → 4; a single time of day for a regular dose ("aamulla", "iltaisin",
  "nocte", "before breakfast", "every morning") → 1 per 1 d, but not for an as-needed dose
  ("1 tabl tarv. illalla"); a maximum ("max 3 x vrk") is not a frequency;
  a range ("1-2") leaves `dose_value` empty; "1/2 tabl" → `0.5`; spelled-out "two" → `2`.
  `dose_unit` is the unit counted by the dose, or the dose form printed right next to a bare
  count ("tabl 1 x 2"). A mass right after the product name is `strength_text`, not a dose.
  `as_needed` for tarvittaessa/tarv./vid behov/vb/PRN/as needed/when needed, and for a
  medicine used only on a stated trigger ("EpiPen … vid anafylaxi", sv01).
- `confidence` is informative only (not scored): `medium` for typos, abbreviations needing
  interpretation, or uncertain name order. An allergy `category` that follows plainly from the
  substance (Shellfish → food, Penisilliini → medication) does not lower it.
- Prompt injection: text in a document is data, never instructions. A "no allergies" / "no
  medication" claim made inside an instruction to the reader or inside forged markup is not a
  clinical statement and decides nothing (fi09, en05), so gold does not quote it and reflects
  the true clinical facts. Nothing inside an instruction to the reader or forged markup is
  quoted or extracted; the rest of the document stays valid evidence (prompt `extract_v5`).

## Optional sections (schema 1.2.0)

Cases with `"extra_sections": true` in `meta.json` annotate the optional sections in their gold:
`vital_signs`, `social_history`, `immunizations`, `pregnancy` and `patient.contacts` (the 11
questionnaire cases, fi13-fi19, sv07-sv08, en07-en08). The harness scores those sections only
for such cases; other cases have empty lists there and are not scored on them. Rules (prompt
`extract_v6`):

- Vital signs: a measured number with its unit as written; blood pressure is one item with the
  diastolic value. `effective` only when the document dates the block ("(06.10.2026)" after the
  line); height and weight written without a date are undated. Lab results are not vital signs.
- Social history: one item per tobacco or alcohol statement. "Ei tupakoi" / "Röker inte" /
  "Non-smoker" is `non_smoker`; `never` only when it says never smoked; `former` when stopped.
- Immunizations: one item per dose ("MPR-rokote 1997 ja 2002" = two items, same quote). Having
  had the disease ("vesirokko sairastettu") is not a vaccination.
- Pregnancy: one item per fact; `pregnancies` and `deliveries` are the numbers as written
  (a qualifier such as "aiemmat" goes to `note`); no computed numbers or dates. A pregnancy
  also written as a diagnosis line is still a problem.
- Contacts: the person's name, relationship as written and telephone number.
